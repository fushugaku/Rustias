# Rustias

[English](README.md) · **Русский**

Rustias — Rust-часть проекта эмуляции Korg RADIAS: нативный синтезатор, интерпретатор оригинальной прошивки, desktop-интерфейс и консольный отладчик. Девять крейтов собраны в один Cargo workspace.

Проект находится в разработке. Отдельные алгоритмы и записанные сценарии сверяются с исходным C++-эмулятором; эти проверки не доказывают полное совпадение с аппаратным RADIAS.

## Два режима работы

- **Нативный синтез** (`radias-synth-*`) исполняет восстановленные алгоритмы напрямую в Rust: осцилляторы, фильтры, огибающие, усилитель, панораму, LFO, модуляцию и управление голосами. Desktop использует пул из 24 голосов и четыре независимо управляемых тембра. Звуковые сэмплы создаются в callback аудиоустройства.
- **Оригинальная прошивка** (`radias-domain`, `radias-application`) исполняется в моделях SH3 и C55 с памятью, периферией и шинами платы. Этот режим нужен для исследования, трассировки и сравнения. Интерпретатор работает медленнее реального времени.

Desktop использует нативный режим, когда доступны необходимые файлы и аудиоустройство. CLI работает с интерпретатором прошивки.

## WebAssembly

[Открыть синтезатор](https://fushugaku.github.io/Rustias/).

Браузерная версия работает без прошивки. Общий Rust-генератор из `radias-synth-infrastructure::synthesizer` создаёт звук внутри Web Audio `AudioWorklet`; JavaScript передаёт команды и выводит звук. Сборка не использует интерпретатор SH3/C55 и SYS-образы; RDL-банки и заводской PCM-ROM в неё не включены. Пользователь может импортировать свои RDL-программы. Сэмплы барабанов — отдельные локальные файлы или включённые в сайт библиотеки ударных.

Все 155 реализованных параметров движка собраны на одной серебристой панели. Их описание берётся из общей [схемы](crates/radias-synth-infrastructure/src/parameters.json), по которой Rust проверяет входные значения.

| Раздел | Возможности |
| --- | --- |
| OSC1 | Saw, Pulse, Triangle, Sine, Noise, Formant; Waveform, Cross, Unison и VPM; CTRL1/CTRL2. Noise/Formant работают в режиме Waveform |
| OSC2 / Mixer | Четыре формы; Normal, Ring, Sync и Ring+Sync; semitone/fine tune; уровни OSC1, OSC2 и Noise |
| Filters | Морфинг Filter1, cutoff, resonance, EG1 и key tracking; Single/Serial/Parallel/Individual; Filter2 LP/HP/BP/Comb, Link, cutoff, resonance, EG1 и key tracking |
| Drive / WS | Отдельные режимы Off / Drive / WavShape; 11 типов WS: Decimator, Hard Clip, OctSaw, MultiTri, MultiSin, четыре SubOSC, Pickup и Level Boost; Depth 0–127 и позиция PreFilt1 / PreAmp. Тип WS и глубина сохраняются при смене режима |
| EG1 / EG2 / EG3 | Независимые ADSR, восемь кривых, чувствительность уровня и времени к velocity, key tracking |
| Amplifier | Уровень, панорама, key tracking, смещение уровня, source gain/Expression и MIDI volume; автоматический gain bank для Unison |
| LFO1 / LFO2 | Форма, shape, частота, фаза, Free/Timbre/Voice sync, tempo sync, деление и смещение скорости |
| Virtual patches | Шесть маршрутов source/destination/intensity, ручные смещения и обратные связи между патчами |
| Voice / Pitch | Четыре тембра, 48 общих веб-голосов, Mono/Poly, retrigger/priority, Unison из 2–8 голосов, detune/spread, portamento time/curve/CC65, transpose, fine tune, bend и vibrato |
| Tuning / MIDI | Одиннадцать строев, тоника, master tune и custom cents; собственный или Global MIDI-канал тембра, клавишные диапазоны и receive flags; ноты, bend, wheel, CC11 Expression, CC64 sustain, CC65, all notes/sound off |
| Drum Kit | 16 независимых инструментов синтеза или сэмплов; тембр-владелец, общий уровень/pan/transpose и Gain −24…+24 dB, trigger note, exclusive group; 224 встроенные записи и загрузка своих файлов |
| Веб-секвенсор | Четыре полифонические дорожки по 1–128 шагов; общий Play. Аккорд, любые сэмплы, выделение и Copy/Paste, velocity и gate каждого шага; независимые длина, включение и длительность шага; восемь блоков по 16 шагов |

Нажмите **Start audio** для воспроизведения. Все разделы синтеза остаются на одной странице; тембр выбирается в верхней панели. При включённом **Drum mode** выберите тембр-владелец и инструмент: регуляторы редактируют этот инструмент, клавиатура превращается в 16 drum pads. Нажатие pad также выбирает его инструмент для редактирования; выбранный pad выделен синей рамкой. Параметры синтеза действуют на этот ударный, а Kit level/pan — на весь набор. Выбор другого инструмента сохраняет звучащие голоса. Громкость прослушивания отделена от уровня тембра.

Новые назначения сэмплов и **808 kit** / **909 kit** используют Filter1 LPF24 (Morph 0) с максимальным Cutoff. Morph 127 — почти обходной режим Thru; он отмечен в заголовке фильтра. В ранее сохранённых наборах поставьте Morph 0, чтобы слышать срез Cutoff. Синтез и PCM делят общий веб-лимит в 48 голосов; при заполнении вытесняются старые голоса. Для PCM осцилляторы, Mono/Unison, portamento и damper для него неактивны. One-shot игнорирует отпускание клавиши, поэтому release огибающих доступен в Gate или Loop. Модуляции LFO/EG нужен активный virtual patch либо ненулевая интенсивность EG фильтра.

Регуляторы поддерживают перетаскивание, точную настройку с Shift, колесо, стрелки, Page/Home/End, ввод числа и сброс двойным кликом. Кнопка полного экрана разворачивает инструмент. На экране 1440×900 помещаются панель синтеза, секвенсор и клавиатура; на небольших экранах доступны прокрутка и крупные элементы для касания.

При включённом **Drum mode** дорожка тембра-владельца показывает названия сэмплов из текущего kit вместо нот. В редакторе шага доступны 16 подписанных drum pads, включая загруженные сэмплы; нажатие проигрывает весь выбранный набор. Названия учитывают **Trigger** и общий **Transpose** набора и обновляются при смене сэмпла. Инструменты синтеза обозначены Drum 01–16. Остальные тембры сохраняют нотную клавиатуру.

У каждого PCM-инструмента есть свои **Key track**, **Level offset**, **Source gain**, **MIDI vol RX** и **MIDI vol**, фильтры, огибающие и Amp level. Для Source gain выберите **Gain source → Manual gain**; Expression использует CC11 тембра-владельца. CC7 меняет громкость только инструментов с включённым MIDI vol RX. Старые браузерные патчи переносят прежний общий ручной gain в назначенные PCM-инструменты; новые изменения сохраняются независимо. Key track учитывает транспонирование высоты сэмпла. Gain bank — автоматический показатель Unison нативных голосов; для PCM он равен 0. Нажатие ударного pad в редакторе секвенсора также выбирает его инструмент для редактирования на панели.

Нажмите шаг секвенсора, чтобы изменить его аккорд. Кнопки **← / →** переключают шаги 1–128 внутри редактора и автоматически меняют отображаемый блок из 16 шагов. Нажатие ноты проигрывает **все выбранные ноты вместе** на тембре этой дорожки — с его звуком, velocity и gate. **Play** запускает все четыре дорожки на одной границе аудиоблока. Длины независимы: одна дорожка может иметь 128 шагов, другая — повторять 16. Список блоков переключает шаги 1–16 … 113–128. У каждой дорожки есть Resolution: 1/32, 1/24, 3/64, 1/16, 1/12, 3/32, 1/8, 1/6, 3/16, 1/4, 1/3, 3/8, 1/2, 2/3, 3/4 или 1/1. Как описано для [RADIAS P15 Resolutn](https://cdn.korg.com/us/support/download/files/c9f9bb7725d303cbc977b6e7cc08d464.pdf#page=106), четверть равна одной доле BPM; триоли и ноты с точкой используют соответствующие доли. Прослушивание аккорда и gate учитывают выбранную длительность. Открытый шаг выделен синей рамкой, воспроизводимый — красной полосой. **Copy next** копирует аккорд, сэмплы, velocity и gate; Alt-клик очищает шаг. Такт работает в AudioWorklet; погрешность начала ограничена одним нативным блоком из 128 кадров. Этот секвенсор существует только в веб-версии; секвенсор desktop и прошивка не меняются.

В любом шаге **Add sample…** позволяет искать по всем 224 записям и своим загрузкам независимо от 16 слотов kit и Drum mode. **Upload** в редакторе добавляет свой файл прямо в шаг. Вместе можно выбрать до 48 нот и источников сэмплов. Нажмите название сэмпла, чтобы редактировать его на основной панели: у каждого источника свои фильтры, огибающие, усилитель, pitch, Drive/WS и модуляции для каждого тембра. **Playback** и **Preview** относятся к выбранному источнику. Добавление сэмпла проигрывает весь выбранный аккорд.

Для выделения включите **Select** и нажмите первый и последний шаг участка; на компьютере можно протянуть по ячейкам или указать конец с Shift-кликом. **Copy** сохраняет ноты, сэмплы, пустые промежутки, velocity и gate. Выберите шаг назначения на любом тембре или следующем участке и нажмите **Paste**; эта кнопка есть и в редакторе шага. Вне текстовых полей работают Ctrl/Cmd+C/V и Undo. Вставка при необходимости увеличивает длину дорожки; обрезка у шага 128 отмечается. При переносе PCM-ударных на другой тембр сохраняются выбранные сэмплы; их настройки копируются, если у нового тембра ещё нет собственного профиля источника.

**Gain · dB** в Drum Kit меняет уровень всего набора ударных и сэмплов шагов в диапазоне −24…+24 dB. Начальное значение **+12 dB** увеличивает амплитуду примерно в четыре раза. У мелодических тембров остаётся собственный уровень. Gain сохраняется в патче и текущем сеансе.

**Save** сохраняет весь патч в localStorage: четыре тембра, 16 инструментов, четыре последовательности, назначения сэмплов, настройки каждого источника и Drum Kit Gain. Патчи появляются в списке Program; повторный Save обновляет выбранный патч. Стрелка рядом с **Save** открывает **Save current** и **Save copy…**. При сохранении копии задайте имя: исходный патч сохранится, а новая копия станет текущей; следующий Save обновит её. Копия сохраняет исходные RDL-записи и назначения сэмплов. Текущий сеанс автоматически восстанавливается после перезагрузки, с остановленным воспроизведением. **Export** и **Import** обмениваются JSON-файлами. Старые нативные программы и веб-последовательности из 16 шагов переносятся автоматически.

**Import** также принимает **.rdl**-бэкапы RADIAS Librarian, неполные банки и отдельные записи программ размером до 8 МиБ. Каждая программа становится сохранённым пользовательским патчем в **Program**: четыре тембра, параметры нативного синтеза, темп, MIDI receive flags и связанный drum kit из 16 инструментов, если он есть в файле. В списке доступен поиск. Повторный импорт того же файла пропускает существующие программы и сохраняет внесённые изменения. Общие данные банка хранятся компактно в localStorage. Повреждённый файл или нехватка места оставляют текущую библиотеку без изменений. Браузер разбирает файл локально в отдельном WASM-worker; бэкап на сервер не отправляется.

Кнопка **RDL** у импортированного патча показывает источник и ограничения переноса. PCM/Audio In недоступны без исходного ROM/входного тракта, поэтому зависимые тембры и ударные молчат до замены источника. Выберите доступную форму **OSC1**; для ударного вместо неё можно назначить встроенный или свой сэмпл. Недоступные маршруты модуляции отключаются; значения за пределами веб-диапазона отмечаются в отчёте. Эффекты, vocoder, аппаратные arpeggiator/motion/step sequences и исходные Global-настройки строя не воспроизводятся; веб-секвенсоры начинают с пустых дорожек. Полные исходные записи программы, связанного drum kit и Global, включая метаданные Librarian, сохраняются в патче и его JSON-экспорте после редактирования. JSON-экспорт не является RDL-файлом для загрузки в аппаратный RADIAS.

В Drum Kit кнопки **808 kit** и **909 kit** назначают 16 инструментам готовые наборы ударных. **Source** выбирает один из 224 встроенных сэмплов или синтез движка; **Search samples** ищет запись по названию, **Upload** загружает свой файл для выбранного инструмента. Браузер декодирует его локально, сводит в моно и пересчитывает в 48 кГц. Максимум — 30 секунд и 20 МБ; доступные форматы зависят от аудиодекодера браузера. Режимы **One-shot** (звучит после отпускания клавиши), **Gate** (отпускание запускает release EG2) и **Loop** (повтор до окончания release). Rust-сэмплер применяет фильтры/Comb, EG1–3, Drive/WS, pitch, LFO/virtual patches, amplifier и pan. Осцилляторные регуляторы для PCM-инструмента неактивны. В браузере синтез, сэмплы kit и сэмплы шагов используют общий лимит в 48 голосов. Desktop сохраняет исходный лимит в 24 голоса.

Свои файлы остаются в IndexedDB на этом устройстве и в этом браузере; на сервер они не отправляются. JSON хранит назначения, а аудио остаётся в IndexedDB. При переносе такого патча в другой браузер загрузите свои файлы там заново. 64 встроенных WAV 808 взяты из [TR-808-набора Michael Fischer](https://github.com/tidalcycles/sounds-tr808-fischer), опубликованного под [CC0-1.0](web/samples/LICENSE.txt). Полный [набор TR-909 Jason Baker / Rob Roy Recordings из 160 записей](https://github.com/fluid-music/open-drums/tree/475cc3314fe06f6d1af02e9790ad9707c1f2b26b/tr-909/TR909all) включён отдельно, с неизменёнными WAV и [исходными условиями](web/samples/tr-909/TR909SET.TXT): набор можно копировать и распространять бесплатно, но нельзя изменять или распространять ради прибыли. Лицензия 909 отличается от CC0. [Манифест](web/samples/manifest.json) хранит лицензию и ревизию источника каждого банка, исходные имена файлов и SHA-256.

Автономный профиль передаёт контроллерам таблицы, рассчитанные по математическим формулам: фильтры, Comb, огибающие, LFO/tempo, модуляция, шум, строй, pan и группы голосов. Интерполяционная коррекция waveform остаётся нулевой. Это самостоятельные данные для общих DSP-алгоритмов; они не копируют заводской ROM и не воспроизводят заводские программы. Оригинальные PCM/Audio In, эффекты FXD03, vocoder и секвенсоры прошивки ещё не завершены в нативном движке. Описанные выше сэмплер и полифонический секвенсор добавлены в веб-версию отдельно.

Собрать и открыть локально:

```sh
rustup target add wasm32-unknown-unknown
bash scripts/build-web.sh
python3 -m http.server 8080 --directory dist
```

Откройте `http://localhost:8080`. Для AudioWorklet нужен HTTPS или localhost. Скрипт создаёт `dist/` с HTML, JavaScript, WAV-библиотекой и `rustias.wasm`; wasm-bindgen, npm и серверная часть не требуются. Нативный поток имеет частоту 48 кГц; Web Audio-адаптер при необходимости пересчитывает его в частоту устройства.

Проверить готовый WASM и AudioWorklet на 48/44,1 кГц можно через `node scripts/verify-web.mjs`. Workflow [pages.yml](.github/workflows/pages.yml) тестирует автономный профиль, собирает WASM и публикует `dist/` в GitHub Pages при push в `main`. Источник публикации в Settings → Pages должен быть **GitHub Actions**.

## Сборка desktop и CLI

Workspace использует Rust edition 2024. Перенос проверен с Rust/Cargo **1.97.1** на macOS. `Cargo.lock` фиксирует зависимости; основные desktop-библиотеки — eframe/egui 0.36.2, CPAL 0.18.2 и midir 0.11.0.

```sh
git clone https://github.com/fushugaku/Rustias.git
cd Rustias

# Консольный эмулятор
cargo build --release --locked -p radias-cli

# Нативное приложение
cargo build --release --locked -p radias-desktop
```

Бинарные файлы появятся в `target/release/radias-rust` и `target/release/radias-desktop`. Для сборки всего workspace:

```sh
cargo build --release --locked --workspace
```

Сборка CLI не подключает аудио- и MIDI-библиотеки. Desktop требует оконного окружения и системных библиотек, используемых CPAL, midir и eframe. Другие операционные системы при переносе не проверялись.

## Данные для запуска

Сборка и обычные unit-тесты обходятся без оригинальных образов. Для desktop-режимов и интерпретатора нужны внешние файлы; браузерный автономный профиль обходится без них. В этом репозитории находятся Rust-исходники, Cargo-манифесты и встроенное описание панели; прошивка, банки, подготовленные программы и исследовательские записи остаются отдельно.

| Файл относительно каталога данных | Для чего нужен |
| --- | --- |
| `firmware/RADIAS_SYS_0200.bin` | Образ SYS 2.00; обязателен для интерпретатора и извлечения таблиц нативного синтеза |
| `firmware/Radias-backup.rdl` | Банк программ; обязателен для нативного desktop-режима, в CLI подключается через `--backup` |
| `firmware/dsp-master-host-stream.bin` | Поток загрузки Master DSP с таблицами для нативного синтеза |
| `assets/native-va/saw.json`, `pulse.json`, `triangle.json`, `sine.json` | Подготовленные параметры нативных голосов; все четыре файла находятся в `assets/native-va/` |
| `assets/native-va/filter-controls.json` | Карта управляющих параметров фильтра для нативного режима |
| `runs/alternative-pcm/alternative-pcm.bin` | Необязательный альтернативный PCM-банк для интерпретатора |

Каталог данных может быть корнем этого репозитория или отдельной папкой с той же структурой. Для продолжения работы с полным исходным проектом передайте его каталог через `--workspace`; копировать данные не требуется.

## Desktop

```sh
# Данные расположены в корне Rustias
cargo run --release --locked -p radias-desktop

# Данные расположены в отдельном каталоге
cargo run --release --locked -p radias-desktop -- \
  --workspace /absolute/path/to/radias-data

# Проверка интерфейса в узком окне без аудиовыхода
cargo run --release --locked -p radias-desktop -- \
  --workspace /absolute/path/to/radias-data --no-audio --size 390x780
```

Панель содержит регуляторы и переключатели RADIAS, выбор программ и экранную клавиатуру. MIDI поступает через виртуальный вход `RADIAS Rust`. Внешние MIDI-байты направляются в выбранный движок.

`--workspace` задаёт каталог исходных данных и рабочих файлов. `--no-audio` отключает аудиовыход и загрузку нативного аудиодвижка; интерпретатору по-прежнему нужен SYS-образ. `--size WIDTHxHEIGHT` задаёт начальный размер окна.

В режиме прошивки рабочий Flash сохраняется в `runs/rust-desktop/working-flash.bin`, а прослушивание — в `runs/rust-desktop/last-preview.wav` и соседние файлы каналов. Flash сохраняет завершённые записи NOR, но не состояние процессоров, RAM и звучащих голосов. Повторный запуск с тем же каталогом данных использует этот рабочий образ.

## Консольный эмулятор

Пути CLI разрешаются относительно текущего каталога; расположение файлов можно указать явно:

```sh
cargo run --release --locked -p radias-cli -- \
  --firmware /absolute/path/to/radias-data/firmware/RADIAS_SYS_0200.bin \
  --backup /absolute/path/to/radias-data/firmware/Radias-backup.rdl \
  --interactive \
  --dry-audio runs/cli/dry.wav \
  --mix-audio runs/cli/mix
```

Интерактивный режим принимает одну команду на строку и отвечает строками JSON. Пример сеанса:

```text
state
run 5000000
midi 90 3c 64
runframes 4800
midi 80 3c 00
runframes 4800
quit
```

`run` задаёт число шагов интерпретатора, `runframes` — число кадров платы с частотой 48 кГц. Байты `midi` записываются шестнадцатерично; в примере это нажатие и отпускание C4 на первом канале. До отправки нот прошивка должна завершить загрузку; один вызов `run` не гарантирует готовность.

| Опция | Назначение |
| --- | --- |
| `--steps N` | Выполнить заданное число шагов без интерактивного сеанса |
| `--backup-global RDL` | Импортировать только Global-настройки из банка |
| `--pcm-bank BIN` | Подключить банк в native Flash-разметке |
| `--flash-image BIN` | Создать или загрузить отдельный рабочий Flash-образ размером 4 МиБ |
| `--input-wave WAV` | Подать mono/stereo WAVE 48 кГц: PCM16/24/32 или float32 |
| `--input-loop` | Повторять входной WAVE |
| `--dry-audio WAV` | Сохранить сухой звуковой поток |
| `--mix-audio PREFIX` | Сохранить native Master/Slave в `PREFIX-master.wav` и `PREFIX-slave.wav` |
| `--vocoder-audio PREFIX` | Сохранить доступные vocoder-потоки |
| `--dump JSON` | Записать диагностическое состояние |
| `--trace PATH`, `--fxd-trace PATH`, `--fxd-link-trace PATH` | Записать диагностические трассы |

Исходные SYS/RDL/PCM/WAVE защищены от перезаписи через выходные пути и их файловые алиасы. Рабочие данные и записи игнорируются Git.

## Проверки

Из корня репозитория:

```sh
cargo test --workspace --all-features --locked
cargo check --workspace --all-targets --all-features --locked
bash scripts/build-web.sh
node scripts/verify-web.mjs
# Проверка своего бэкапа без изменения файла:
node scripts/verify-rdl.mjs dist/rustias.wasm /absolute/path/to/backup.rdl
```

Unit-тесты проверяют маршрутизацию программ, форматы WAVE, защиту исходных файлов, аудиобуферы, интерфейс и автономный синтез. WASM-проверка воспроизводит все поддерживаемые режимы OSC1, маршруты Filter2 и типы waveshaper; проверяет модуляцию, mono/unison, MIDI Expression, Drum Kit, воспроизведение и обработку PCM, контрольные суммы всех 224 записей, независимые настройки Amplifier сэмплов и приём CC7, общий Gain ударных, 48 голосов, любые сэмплы в шагах и копирование участков, 128 шагов, прослушивание целого аккорда и сохранение патчей. Для RDL используется синтетический банк из 256 программ и 32 наборов ударных: проверяются параметры, исходные записи, отключение недоступных источников, частичные банки и отдельные программы, повреждённые файлы, повторный импорт, перенос старой библиотеки и атомарный отказ при нехватке места. Тест реального аудиовыхода помечен `ignored`: ему нужны исходные данные и устройство вывода.

Rust-примеры в `crates/*/examples/` сохранены вместе с кодом. Многие `*_parity`-программы читают эталонные записи, полные WAV и состояния из внешнего исследовательского workspace. Такие сравнения требуют соответствующих данных и C++-оракулов исходного проекта; они не входят в обычный запуск unit-тестов. В примерах, которые принимают каталог данных первым аргументом, передавайте его явно.

Сгенерированные декодеры SH3/C55 включены в исходники и собираются обычным Cargo. Для их регенерации нужны C++-источники и генераторы из полного проекта; этот репозиторий содержит готовый Rust-результат.

## Текущие ограничения

- Полное исполнение произвольных RDL-программ и всех сочетаний параметров ещё не завершено.
- Эффекты FXD03, конечный codec/DAC-тракт и аппаратные тайминги требуют дальнейшей проверки. Записи до FXD/codec не следует считать окончательным выходом физического RADIAS.
- Некоторые контроллерные сценарии, политики голосов, секвенсор, vocoder и аппаратные органы управления остаются неполными.
- Режим прошивки может давать underrun при прослушивании; он предназначен для диагностики. Скорость отдельных нативных алгоритмов не подтверждает готовность всего инструмента к работе в реальном времени.
- Заводской PCM-ROM в репозиторий не входит. Альтернативный PCM-банк не воспроизводит отсутствующий заводской банк.

Совпадение с программным эталоном подтверждает только проверенный сценарий и наблюдаемую границу. Полная аппаратная эквивалентность остаётся целью проекта.
